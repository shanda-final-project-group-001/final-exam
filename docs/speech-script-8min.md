### 3.2 高频问题

**Q1：为什么用 Deep Agents，而不是自己写一个循环？**

**林至言：** 因为路径 A 要求开源 Agent 框架，而 Deep Agents 直接给了我们五样东西：`write_todos` 多步规划、Skills 发现、`AGENTS.md` 长期记忆、子代理审阅、文件权限。我们不用重复造调度循环，可以把时间放在业务工具和确认链路上。代价是框架有学习成本，所以我们固定了版本，并写了 `check_agent` 自检，确保工具、Skill、权限都真的挂上了。

**Q2：Skill 和系统提示词有什么区别？**

**林至言：** 系统提示词每轮都在，负责角色、边界和回答风格；Skill 是按需读取的过程知识。比如“怎么给活动打分排序”“周报按什么章节写”，放在 `SKILL.md` 里，模型需要时用 `read_file` 读，不常驻上下文。这样规则可以独立修改，也不会把提示词撑爆。现场执行面板里能看到 `read_file` 的那一步。

**Q3：如果模型不调工具、直接编一个活动怎么办？**

**朱煜杰：** 三层防护。第一，系统提示明确要求“活动、名额、时长只能来自工具返回”，错误原样转述；第二，所有数据都在 SQLite 里，模型没有别的数据源，编出来的编号一查就是 `NOT_FOUND`；第三，界面把每次工具调用和返回都展示出来，老师能当场核对。我们测过 `A999` 和满员活动，模型会转述 `NOT_FOUND` / `FULL`，不会硬写。

**Q4：MCP 服务器和普通工具有什么区别？为什么不全做成 MCP？**

**朱煜杰：** MCP 是标准协议，解决“能力怎么被不同客户端复用”。我们的三个只读工具注册在 `volunteer-data` 服务器里，Agent 直接复用同一份定义，别的 MCP 客户端也能连。写工具没放 MCP，是因为报名、取消需要 `interrupt` 人工确认、事务和权限控制，放在 Agent 本地包装层更直接。简单说：读能力标准化，写能力守住确认边界。

**Q5：冲突是怎么判断的？数据表怎么设计？**

**朱煜杰：** 五张表：学生、课程、活动、报名、时长。冲突判断是确定性的区间重叠：同一天，活动时间段和学生课表或已确认报名的时间段有交集，就算冲突。报名在单个事务里依次校验学生、活动状态、重复报名、名额、冲突；剩余名额不落库，实时算，避免数据漂移；取消是软删除，重复取消幂等。现场看到的 `CONFLICT` 就是工具算出来的，不是模型猜的。

**Q6：密钥怎么保护？Agent 能不能读到 `.env`？**

**林至言：** 密钥只放 `.env`，`.gitignore` 已忽略，仓库里只有 `.env.example` 占位符；界面不显示 Key。Agent 的文件权限里，`.env`、`.venv`、`data/` 是拒绝读写的，业务产出只能写 `workspace/`；`AGENTS.md` 单独放行，因为它就是长期记忆文件。演示数据全部虚构，不涉及真实个人信息。

**Q7：怎么证明“长期记忆”不是模型编的？**

**朱煜杰：** 记忆存在仓库根目录的 `AGENTS.md`，由 Memory 中间件每轮注入。文件里的用户偏好只有四条：①校内优先、周末优先，校外提醒通勤；②先结论后理由，列表不超过 3 条；③冲突只说事实，不替用户决定换课；④输出简体中文，时间统一格式。**没有常空时段**。可以当场问：“只依据长期记忆文件，里面有没有记录我的常空时段？”执行面板会出现 `read_file /AGENTS.md`，回答是“没有记录”，并列出真实存在的四条。常空时段来自 `students` 画像表，是另一回事。它敢说“没有”，恰好证明不是靠上下文编的。

**Q8：相对 demo_5，你们到底加了什么？**

**林至言：** 四类增量：新业务闭环（校园志愿）、新 MCP 服务器 `volunteer-data`、四个自定义工具和两个自写 Skill、报名二次确认与写权限隔离；另外还有周报/CSV 产出、双库会话、Docker 和 36 项单元测试。代码位置分别是 `volunteer/agent.py`、`volunteer/mcp_server.py`、`volunteer/tools_business.py`、`volunteer/skills/`，老师可以任选一处现场打开。

**Q9：刷新页面或关掉浏览器，会话还在吗？**

**林至言：** 在。业务数据在 `data/volunteer_demo.db`；会话历史和对话内容由 `volunteer/sessions.py` 写 SQLite；Agent 的图状态用 LangGraph 的 SQLite checkpointer 存到 `data/agent_state.db`，包括待确认的 `interrupt`。刷新后侧边栏还能选回原会话，多轮上下文和待确认操作都不会丢；“新建对话”会换一个 thread_id，互不干扰。

## 4. 排练与超时处理

### 4.1 三次排练

| 轮次 | 内容 | 通过标准 |
|---|---|---|
| 第 1 轮 | 两人各自念自己的段落，不看秒表 | 每句能顺下来，不念方括号 |
| 第 2 轮 | 完整走台 + 真实演示 | 1:50、3:50、7:20 三个检查点误差 ≤ 15 秒 |
| 第 3 轮 | 模拟提问 + 故障切换 | 任意故障 10 秒内能接上备用口令 |

### 4.2 超时怎么砍

- 超过 1:50：第 2 页目录只念一句“今天讲六件事”，直接翻页。
- 超过 3:50：合规页压成一句话“只做正当需求、数据最小化、写操作确认、结果可核验”，然后立刻进演示。
- 超过 7:20：不足页只讲“数据是样例、未接真实系统、下一步接接口和 RAG”，致谢照常。
- **不砍**：报名确认和周报产出。这两段是评分点，也是现场最直观的证据。
