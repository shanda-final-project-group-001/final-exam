# 志愿时长周报

输入是 `get_volunteer_hours(student_id, term)` 的返回值，输出是一份 Markdown 周报，
写入 `workspace/reports/weekly-report-<YYYY-MM-DD>.md`。

## 1. 三条硬规矩

1. **数字只从工具来。** 总时长、条数、每次活动的小时数都必须是工具返回值里的字段。
   工具没返回的（比如“全年级排名”“折算学分”）一律不写，也不估算。
2. **只写 `workspace/`。** 路径必须是相对 `workspace/` 的名字；写别处会被拒绝。
3. **标注样例。** 页脚固定写“数据来源：本地演示样例数据”，避免被当成学校正式认定结果。

## 2. 生成步骤

1. 调用 `get_volunteer_hours(student_id, term)`。
2. 如果返回里有 `error`，直接把中文提示转述给用户，**不要生成周报文件**。
3. 若 `records` 为空：告诉用户“本学期暂无已认定时长”，问是否换学期查询，不写文件。
4. 调用 `export_hours_csv(student_id, term)`，导出明细 CSV（Excel 可直接打开）。
5. 调用 `write_file` 写入周报，路径 `workspace/reports/weekly-report-<今天日期>.md`。
6. 回复里给出两个文件路径，并用 3 句话概括本周报的结论。

## 3. 内容要求

严格按 `template.md` 的章节顺序写，缺数据就写“暂无”，不要删章节。

- **概览表**：总时长、活动次数、服务类别数、最大单次时长。
- **明细表**：按日期升序，一活动一行；小时数保留一位小数。
- **小结**：只描述事实，例如“本月 6 次活动共 18.5 小时，以助老与环保为主”。
- **下一步建议**：结合 `search_activities` 的余额，给 1–2 个可报名的活动；没有查询过就不要写具体编号。

## 4. 写完自检（critic 子代理会按这张表挑错）

| 检查项 | 不合格示例 |
|---|---|
| 总时长与明细能对上 | 明细相加 18.5，概览写 20 |
| 每条明细都有活动编号 | 只写“图书馆整理” |
| 日期格式统一 | 混用 10/17 与 2026-10-17 |
| 没有编造数据 | 出现“排名第 3” |
| 有样例声明 | 页脚缺失 |
| 文件在 workspace 下 | 写到 `../reports` |

## 5. 措辞

- 用“已认定时长”而不是“公益时长”，与学校口径一致。
- 涉及认定规则时提示“以学校官方最新文件为准”。
- 不用夸张修辞，不写“表现优异”“获一致好评”之类没有依据的评价。
